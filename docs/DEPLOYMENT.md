# דיפלוימנט

## ההמלצה בקצרה

**Vercel (אפליקציה) + Supabase (בסיס נתונים, אימות, פוש) — בעלות 0 ₪ לחודש.**

בקנה מידה משפחתי שתי התוכניות החינמיות מספיקות בנוחות, אין שרת לתחזק, ה-HTTPS
מסודר מעצמו, וכל דחיפה ל-GitHub מעלה גרסה חדשה. הדבר היחיד ששווה כסף הוא דומיין
משלכם, בערך 40–60 ₪ לשנה, וגם הוא לא חובה.

**למה לא נייטיב.** אפליקציה נייטיבית קונה שני דברים אמיתיים — ווידג׳טים במסך
הבית ופוש אמין יותר — ומשלמת עליהם בדמי מפתח שנתיים, ביקורת חנות על כל עדכון,
ושני קוד-בייסים. עבור משפחה, PWA מותקנת נותנת חוויה כמעט זהה. אם בעוד חצי שנה
יתברר שהפוש ב-iOS לא מספיק אמין — אפשר לעטוף את אותה אפליקציה ב-Expo בלי לכתוב
אותה מחדש.

## העלאה לאוויר, צעד אחר צעד

### 1. Supabase

1. פתח פרויקט חדש ב-[supabase.com](https://supabase.com), אזור `eu-central-1`
   (פרנקפורט — הכי קרוב לישראל, בערך 60ms).
2. הדבק את [`schema.sql`](./schema.sql) ב-SQL Editor והרץ.
3. Authentication → Providers → הפעל **Google** (ו-**Magic Link** לבני משפחה
   ללא חשבון גוגל).
4. Authentication → URL Configuration → הוסף את כתובת ה-Production ואת
   `http://localhost:3000` לרשימת ה-Redirect URLs.
5. העתק מ-Settings → API את `Project URL` ואת `anon key`.

### 2. Vercel

1. חבר את ריפוזיטורי ה-GitHub ב-[vercel.com](https://vercel.com). Next.js מזוהה
   אוטומטית, אין מה להגדיר בבנייה.
2. הגדר משתני סביבה:

   | משתנה | היכן משיגים | חשוף לדפדפן |
   |---|---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Settings → API | כן |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase → Settings → API | כן |
   | `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API | **לא — שרת בלבד** |
   | `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | `npx web-push generate-vapid-keys` | כן |
   | `VAPID_PRIVATE_KEY` | מאותה פקודה | **לא — שרת בלבד** |

3. Deploy. כל דחיפה ל-`main` מעלה לפרודקשן, וכל Pull Request מקבל כתובת תצוגה
   מקדימה משלו.

> `SUPABASE_SERVICE_ROLE_KEY` עוקף את כל מדיניות ה-RLS. הוא נחוץ רק לפעולות
> צד-שרת כמו שליחת תזכורות, ואסור שיופיע במשתנה עם קידומת `NEXT_PUBLIC_`.

### 3. דומיין (אופציונלי)

דומיין ב-Cloudflare או Namecheap, הפניית DNS ל-Vercel, תעודת SSL אוטומטית.
כתובת כמו `mishpacha.app` נזכרת הרבה יותר טוב מכתובת `vercel.app` אקראית —
וזה משפיע על השימוש בפועל.

### 4. תזכורות בקרון

Supabase → Edge Functions, פונקציה שרצה כל 15 דקות (דרך `pg_cron` או
Vercel Cron). היא אינה מחשבת מתי להתריע — החישוב כבר נעשה בטריגרים — אלא רק
שולפת מ-`event_reminders` את השורות שבהן `fire_at <= now()` ו-`sent_at is null`,
שולחת Web Push, ומעדכנת `sent_at`.

הפרדה זו חשובה: אם הקרון נפל לשעה, התזכורות שהוחמצו עדיין בתור וניתן לראות
בדיוק מה לא נשלח.

## שני דברים שאסור לדלג עליהם

**גיבויים.** בתוכנית החינמית של Supabase שמירת הגיבויים מוגבלת בזמן. סקריפט
`pg_dump` שבועי ב-GitHub Actions, שמעלה קובץ לדרייב או ל-S3, הוא כמה עשרות
שורות ששוות את זמנן ברגע שהמשפחה תלויה במידע.

**השבתה בגלל חוסר פעילות.** פרויקט Supabase חינמי מושהה אחרי כשבוע ללא פעילות
ודורש הפעלה ידנית. שימוש משפחתי יומיומי לא מגיע לשם; אם בכל זאת יש חשש, בדיקת
בריאות יומית מ-GitHub Actions פותרת את זה.

## אם בכל זאת אחסון עצמי

רלוונטי כשחשוב שהמידע — במיוחד התורים הרפואיים — לא ישב אצל ספק חיצוני.

- **חומרה:** Hetzner CX22 בכ-€4 לחודש, או Raspberry Pi 5 בבית עם
  Cloudflare Tunnel (חושף את השירות בלי לפתוח פורטים בראוטר).
- **הרצה:** Docker Compose עם שלושה שירותים — אפליקציית Next.js, Postgres,
  ו-Caddy כ-reverse proxy עם HTTPS אוטומטי. [Coolify](https://coolify.io)
  נותן חוויית PaaS דמוית-Vercel מעל השרת שלכם, כולל דיפלוי מ-Git.
- **המחיר האמיתי אינו כספי:** עדכוני אבטחה, גיבויים, וניטור הופכים לאחריותכם.
  בפרויקט של סופי שבוע זו הסיבה השכיחה ביותר לנטישה.
