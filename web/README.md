# web — אפליקציית הבית

Next.js 15 (App Router) + TypeScript + Tailwind v4, מעל Supabase.
זהו קוד הייצור. אב הטיפוס להדגמה נשאר ב-[`../poc/index.html`](../poc/index.html).

**מצב נוכחי: שלבים 0–6 הושלמו.**

- **שלב 0** — התחברות, הקמת משק בית, ניהול בני משפחה, הזמנות, ומעטפת ניווט.
- **שלב 1** — רשימת קניות ומלאי הבית, מסונכרנים חי בין מכשירים, עם שני
  הטריגרים שמחברים ביניהם.
- **שלב 2** — יומן חודשי, תורים רפואיים, חזרתיות, ימי הולדת נגזרים ותזכורות.
- **שלב 3** — משימות עם אחראי, דדליין, עדיפות וסטטוס, שמופיעות גם ביומן.
- **שלב 4** — התראות פוש, העדפות פר-אדם, שעות שקט, וקרון כל רבע שעה.
- **שלב 5** — רשימת קניות שעובדת ללא קליטה, מסך בית מסכם, חיפוש רוחבי
  וייצוא גיבוי.
- **שלב 6** — חיווט העמודות שהיו בסכימה בלי ממשק: כיבוי השלמה אוטומטית,
  תאריכי תפוגה, משימות חוזרות, הפניה וביקורת בתור.

**חשוב באייפון:** התראות עובדות רק אחרי «הוסף למסך הבית». מסך ההגדרות
מזהה את המצב ומדריך, אבל בלי ההתקנה לא תגיע שום התראה.

## הרצה מקומית

### 1. פרויקט Supabase

1. פתחו פרויקט ב-[supabase.com](https://supabase.com), אזור `eu-central-1`.
2. הריצו את [`../docs/schema.sql`](../docs/schema.sql) ב-SQL Editor.
   זה יוצר את הטבלאות, הטריגרים, מדיניות ההרשאות ושתי פונקציות ההצטרפות.
   **מריצים גרסה מעודכנת על פרויקט קיים?** הריצו קודם
   [`../docs/reset.sql`](../docs/reset.sql) — הסכימה משתמשת ב-`create table`
   ולכן הרצה חוזרת על טבלאות קיימות תיכשל. הוא מוחק את כל נתוני האפליקציה,
   אך לא את חשבונות המשתמשים.
3. Authentication → Providers → הפעילו **Google**, ובנוסף **Email** עבור
   קישורי כניסה.
4. Authentication → URL Configuration → הוסיפו ל-Redirect URLs את
   `http://localhost:3000/**` ואת כתובת הפרודקשן.

### 2. משתני סביבה

```bash
cp .env.example .env.local
```

ומלאו מ-Settings → API:

| משתנה | חשוף לדפדפן |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | כן |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | כן |
| `NEXT_PUBLIC_SITE_URL` | כן |
| `SUPABASE_SERVICE_ROLE_KEY` | **לא — שרת בלבד.** הקרון משתמש בו |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | כן |
| `VAPID_PRIVATE_KEY` | **לא — שרת בלבד** |
| `CRON_SECRET` | **לא — שרת בלבד** |

מפתחות ה-VAPID נוצרים פעם אחת:

```bash
npx web-push generate-vapid-keys
```

בלי שני הראשונים כל הניווט מוביל למסך `/setup` שמסביר מה חסר, במקום ליפול
בשגיאה.

### 3. הרצה

```bash
npm install
npm run dev
```

### 4. תזמון ההתראות

אחרי שהאפליקציה באוויר, הריצו את [`../docs/cron.sql`](../docs/cron.sql)
ב-SQL Editor — יש בו שתי שורות להחליף. הוא מתזמן קריאה ל-`/api/cron/notify`
כל רבע שעה דרך `pg_cron`.

### 5. נתוני בדיקה (אופציונלי)

אחרי שנכנסתם והקמתם משק בית, הריצו את [`../docs/seed.sql`](../docs/seed.sql)
ב-SQL Editor. הוא מוסיף את שאר בני המשפחה, שמונה פריטי מלאי ושלושה אירועים,
כך שיש מה לבדוק בלי להזין הכול ביד. שלושה פריטים נזרעים מתחת לסף בכוונה,
כדי שהטריגר ייצור להם פריטי קניות מיד.

## מה קורה בכניסה ראשונה

```
/ ─┬─ אין משתמש          → /login
   ├─ יש משתמש, אין שיוך  → /onboarding  (יצירת משק בית)
   └─ יש שיוך            → /home
```

אחרי יצירת משק הבית מגיעים ל-`/family`, שם מוסיפים את שאר בני הבית ומייצרים
עבורם קישורי הזמנה.

### הזמנת בני משפחה

בן משפחה נוצר תחילה כשורה **בלי חשבון** — שם, תפקיד, צבע ותאריך לידה. זו לא
עקיפה של המודל אלא חלק ממנו: ילד בן ארבע צריך תור רפואי ויום הולדת ביומן,
ולא חשבון גוגל.

כשרוצים לתת לו גישה, לוחצים «הזמנה» ומקבלים קישור חד-פעמי לשליחה בוואטסאפ.
הקישור תקף שבועיים, נצרך פעם אחת, וקושר את החשבון של מי שפתח אותו לאותה
שורה בדיוק.

## החלטות שכדאי להכיר לפני שנוגעים בקוד

**`getUser()` ולא `getSession()`.** `getSession()` קורא את העוגייה בלבד, וזו
נשלטת על ידי הלקוח. כל בדיקת הרשאה במערכת עוברת דרך `getUser()`, שמאמת מול
Supabase.

**שתי פונקציות `security definer`, בכוונה.** `create_household` ו-`claim_invite`
רצות כשלמשתמש עדיין אין שיוך למשק בית, ולכן מדיניות ה-RLS הרגילה הייתה חוסמת
אותן. אלה נקודות הכניסה היחידות שעוקפות אותה, והן מצומצמות בדיוק לשני
התרחישים האלה.

**כל תאריך מחושב באזור הזמן של משק הבית — בשני הכיוונים.**

בקריאה: השרת רץ ב-UTC והטלפון לא, ולכן המרה נאיבית של instant לתאריך
מייצרת HTML שונה בכל צד ו-hydration mismatch. השתמשו ב-`zonedDate` / `nowIn`
ולא ב-`new Date(iso)`.

בכתיבה: `new Date("2026-08-12T16:30")` נפתר לפי אזור הזמן של **השרת**, כלומר
UTC בפרודקשן — מה שהיה שומר כל אירוע שלוש שעות מאוחר מדי. השתמשו ב-
`zonedTimeToInstant` מ-`src/lib/calendar.ts`.

**כשל רשת אינו מפיל את האפליקציה.** אם Supabase לא זמין, ה-middleware מתייחס
לכך כ"אין משתמש" ומעביר למסך ההתחברות — שהוא ציבורי, ולכן אין לולאה.

**חיבור מחדש ל-Realtime מושך את הטבלה מחדש.** Realtime אינו משחזר אירועים
שקרו בזמן שהחיבור היה מנותק, ובטלפון ניתוק הוא המצב הרגיל ולא החריג. בלי
המשיכה הזו הרשימה נשארת שגויה ונראית תקינה — וזו בדיוק התקלה שהמודול הזה
אמור למנוע. `useRealtimeRows` מזהה `SUBSCRIBED` שני ומשדר `RESET`.

**אופליין קיים לרשימת הקניות בלבד, וזה מכוון.** הסופר הוא המקום עם הקליטה
הגרועה, ושם כישלון בהוספת פריט הורס את ההרגל שכל השאר תלוי בו. `src/lib/offline.ts`
מחזיק תצלום של המסך ותור פעולות ב-localStorage; ה-service worker מגיש את
הדף **ואת קבצי ה-JS שלו** — דף מטמון שלא מצליח למשוך את הסקריפטים שלו
נראה כמו אפליקציה שבורה, לא כמו אפליקציה במצב אופליין.

פעולה יורדת מהתור רק אחרי שהצליחה, כך שחלון קליטה קצר ממשיך מאיפה שנעצר.
פריט שנוסף אופליין מקבל מזהה זמני, ו-`addShoppingItem` מחזיר את המזהה
האמיתי כדי שהפעולות שמפנות אליו ייכתבו מחדש. מאותה סיבה גם המסלול המקוון
מאמץ את המזהה האמיתי מיד — אחרת אירוע ה-INSERT שמגיע ב-Realtime נושא מזהה
אחר, אינו מוצא התאמה, והפריט מצויר פעמיים.

**עמודה בלי ממשק היא קוד מת, לא תכונה חלקית.** שלב 6 חיווט שבעה כאלה. אם
אתם מוסיפים עמודה לסכימה, הוסיפו את המסך באותה נשימה — אחרת הטריגר מכבד
הגדרה שאיש אינו יכול לשנות, וזה נראה כמו באג.

**מצב בהיר בלבד, בכוונה.** אין `prefers-color-scheme` ואין `[data-theme]`
ב-`globals.css`, ואל תוסיפו: המסכים הבהירים הם אלה שאושרו. שתי נגזרות —
`color-scheme: light` על `:root` מונע מהדפדפן להכהות פקדים שהוא מצייר בעצמו
(בוררי תאריך, רשימות נפתחות, תיבות סימון), וכל משטח חייב רקע מטוקן, כי
משטח שקוף על טלפון במצב כהה יירש רקע כהה.

**טוקנים ולא CSS ישיר.** כל הצבעים מוגדרים כמשתני CSS ב-`globals.css` וממופים
לכלי Tailwind. אל תכתבו צבע ישירות בקומפוננטה.
`--on-pastel` תקף **רק** מעל צבעי בני המשפחה הקבועים.
שימו לב ש-`--danger` אינו כהה מספיק מעל מילוי ורוד — הוא נותן 4.34:1,
מתחת ל-AA — ולכן תווית על `bg-danger-pastel` חייבת `text-danger-ink`.

**הטיפוסים ב-`src/lib/types.ts` כתובים ביד.** ברגע שהפרויקט חי, החליפו אותם
בטיפוסים מיוצרים:

```bash
npx supabase gen types typescript --project-id <id> > src/lib/types.ts
```
