# web — אפליקציית הבית

Next.js 15 (App Router) + TypeScript + Tailwind v4, מעל Supabase.
זהו קוד הייצור. אב הטיפוס להדגמה נשאר ב-[`../poc/index.html`](../poc/index.html).

**מצב נוכחי: שלבים 0–1 הושלמו.**

- **שלב 0** — התחברות, הקמת משק בית, ניהול בני משפחה, הזמנות, ומעטפת ניווט.
- **שלב 1** — רשימת קניות ומלאי הבית, מסונכרנים חי בין מכשירים, עם שני
  הטריגרים שמחברים ביניהם.

מסכי היומן והמשימות עדיין מצייני מקום, וממתינים לשלבים 2–3.

## הרצה מקומית

### 1. פרויקט Supabase

1. פתחו פרויקט ב-[supabase.com](https://supabase.com), אזור `eu-central-1`.
2. הריצו את [`../docs/schema.sql`](../docs/schema.sql) ב-SQL Editor.
   זה יוצר את הטבלאות, הטריגרים, מדיניות ההרשאות ושתי פונקציות ההצטרפות.
3. Authentication → Providers → הפעילו **Google**, ובנוסף **Email** עבור
   קישורי כניסה.
4. Authentication → URL Configuration → הוסיפו ל-Redirect URLs את
   `http://localhost:3000/**` ואת כתובת הפרודקשן.

### 2. משתני סביבה

```bash
cp .env.example .env.local
```

ומלאו מ-Settings → API:

| משתנה | חשוף לדפדפן |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | כן |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | כן |
| `NEXT_PUBLIC_SITE_URL` | כן |
| `SUPABASE_SERVICE_ROLE_KEY` | **לא — שרת בלבד**, ולא נחוץ עד שלב 4 |

בלי שני הראשונים כל הניווט מוביל למסך `/setup` שמסביר מה חסר, במקום ליפול
בשגיאה.

### 3. הרצה

```bash
npm install
npm run dev
```

## מה קורה בכניסה ראשונה

```
/ ─┬─ אין משתמש          → /login
   ├─ יש משתמש, אין שיוך  → /onboarding  (יצירת משק בית)
   └─ יש שיוך            → /home
```

אחרי יצירת משק הבית מגיעים ל-`/family`, שם מוסיפים את שאר בני הבית ומייצרים
עבורם קישורי הזמנה.

### הזמנת בני משפחה

בן משפחה נוצר תחילה כשורה **בלי חשבון** — שם, תפקיד, צבע ותאריך לידה. זו לא
עקיפה של המודל אלא חלק ממנו: ילד בן ארבע צריך תור רפואי ויום הולדת ביומן,
ולא חשבון גוגל.

כשרוצים לתת לו גישה, לוחצים «הזמנה» ומקבלים קישור חד-פעמי לשליחה בוואטסאפ.
הקישור תקף שבועיים, נצרך פעם אחת, וקושר את החשבון של מי שפתח אותו לאותה
שורה בדיוק.

## החלטות שכדאי להכיר לפני שנוגעים בקוד

**`getUser()` ולא `getSession()`.** `getSession()` קורא את העוגייה בלבד, וזו
נשלטת על ידי הלקוח. כל בדיקת הרשאה במערכת עוברת דרך `getUser()`, שמאמת מול
Supabase.

**שתי פונקציות `security definer`, בכוונה.** `create_household` ו-`claim_invite`
רצות כשלמשתמש עדיין אין שיוך למשק בית, ולכן מדיניות ה-RLS הרגילה הייתה חוסמת
אותן. אלה נקודות הכניסה היחידות שעוקפות אותה, והן מצומצמות בדיוק לשני
התרחישים האלה.

**כשל רשת אינו מפיל את האפליקציה.** אם Supabase לא זמין, ה-middleware מתייחס
לכך כ"אין משתמש" ומעביר למסך ההתחברות — שהוא ציבורי, ולכן אין לולאה.

**טוקנים ולא CSS ישיר.** כל הצבעים מוגדרים כמשתני CSS ב-`globals.css` וממופים
לכלי Tailwind. אל תכתבו צבע ישירות בקומפוננטה: המצב הכהה ייראה שבור.
`--on-pastel` תקף **רק** מעל צבעי בני המשפחה הקבועים, ולא מעל מילויים שמתחלפים
עם המצב.

**הטיפוסים ב-`src/lib/types.ts` כתובים ביד.** ברגע שהפרויקט חי, החליפו אותם
בטיפוסים מיוצרים:

```bash
npx supabase gen types typescript --project-id <id> > src/lib/types.ts
```
